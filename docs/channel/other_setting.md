# 渠道额外设置说明

该配置用于设置一些额外的渠道参数，可以通过 JSON 对象进行配置。主要包含以下三个设置项：

1. force_format
    - 用于标识是否对数据进行强制格式化为 OpenAI 格式
    - 类型为布尔值，设置为 true 时启用强制格式化

2. proxy
    - 用于配置网络代理
    - 类型为字符串，支持 `http`、`https`、`socks5` 和 `socks5h` 协议
    - 保存时必须包含协议和主机；仅允许空路径或根路径 `/`，不允许 query 或 fragment
    - SOCKS 代理未填写端口时，运行时使用默认端口 `1080`

3. thinking_to_content
   - 用于标识是否将思考内容`reasoning_content`转换为`<think>`标签拼接到内容中返回
   - 类型为布尔值，设置为 true 时启用思考内容转换

--------------------------------------------------------------

## JSON 格式示例

以下是一个示例配置，启用强制格式化并设置了代理地址：

```json
{
    "force_format": true,
    "thinking_to_content": true,
    "proxy": "socks5://proxy.example:1080"
}
```

--------------------------------------------------------------

通过调整上述 JSON 配置中的值，可以灵活控制渠道的额外行为，比如是否进行格式化以及使用特定的网络代理。

## 升级兼容性

旧版本会忽略代理地址中的 path、query 和 fragment。为避免升级后中断已有渠道流量，运行时会继续剥离这些遗留后缀，并对同一代理地址每个进程记录一次不含凭证和后缀的警告。该兼容逻辑不会改写数据库；再次保存渠道时必须按上述严格规则修正代理地址。

代理连接使用 30 秒 TCP 拨号超时和 30 秒 KeepAlive；TLS 握手超时为 10 秒。这些超时同样适用于未配置渠道代理的中转请求。

## 渠道最大并发请求数

在渠道编辑的「高级设置 → 路由策略」中配置「最大并发请求数」。API 顶层字段为 `max_concurrency`，不是 `setting` JSON 内的字段。

- 未配置或 `0` 表示不限制；允许的正整数范围为 `1–100000`。旧渠道保持不限并发，更新其他字段时省略该字段不会清除已有上限；显式传 `0` 可恢复不限。
- 以渠道 ID 计数，同一渠道的所有模型和多 Key 共用上限。普通请求处理结束、失败或取消后释放名额；流式及 Realtime 请求持续占用到结束。
- 已选渠道满载时直接返回 HTTP `429`，错误码为 `channel_concurrency_limit`；即使其他渠道空闲，本功能也不额外切换渠道或触发重试，不改变既有选路规则。容量不足不触发渠道自动封禁。跨渠道分流或故障转移应由明确的分流功能控制，不从渠道数量、权重或普通重试配置中推断。
- 显式指定渠道、禁止重试的亲和性规则，以及异步任务绑定的原渠道不因满载而切换。
- 异步生成按提交请求计数，不计后台生成时长；后台状态轮询和管理端渠道测试不属于此限制范围。Midjourney 绑定原任务渠道的后续生成操作同样检查原渠道上限。
- 没有 Redis 时只在当前进程内计数；启用 Redis 后，各实例共享原子租约。租约每 10 秒续期、30 秒过期，避免进程崩溃永久占用名额。无法确认续租时取消当前上游请求；Redis 获取租约失败返回 HTTP `503`，不会降级为各实例独立放行。
- 渠道配置遵循现有缓存刷新机制；多实例修改上限后的可见时间由现有渠道缓存同步周期决定。租约无法消除网络分区时上游停止处理的延迟，也无法限制上游接受异步任务后自行执行的并发数。

验证覆盖本地/Redis 原子上限、幂等释放、租约续期与过期清理、不因满载重新选路、满载 429、流式取消释放，以及配置从有限值恢复为 0。

## Magpie 渠道

- 在渠道编辑「高级设置 → 路由策略」开启「Magpie 渠道」（`settings` JSON 的 `magpie_enabled`，默认关闭）。主节点的系统任务按北京时间 09:00–22:00 每 2 分钟、22:00–次日 09:00 每 30 分钟使用渠道的地址、网关密钥和代理/HTTP 连接设置查询 Magpie，不受服务器时区影响。间隔从上次任务结束起计算，跨时段按当前时间重新判断，不要求在整点或整分触发；地址支持根地址、以 `/v1` 结尾的地址以及部署路径前缀。
- 先访问 `GET /v1/magpie/quotas` 初始化额度缓存，再访问 `POST /v1/magpie/quotas/refresh?provider=codex` 刷新并获取账号卡片。GET 没有返回 Codex 卡片时，改用不带 provider 的完整刷新，避免首次读取超时产生的空缓存被当作没有账号；判断仍只使用 Codex 卡片。需要支持该接口和 Codex `held` 状态的新版 Magpie。远程访问需开启 Magpie 的网络共享，使用有效的网关密钥。
- 仅判断 `provider=codex`、`kind=subscription` 的账号。至少一个新鲜、无错误的账号卡片 `held=false` 时可用；所有账号明确不可用（或确实没有 Codex 账号）时禁用。`held` 由 Magpie 综合五小时窗口、周窗口和 credits 判断；不按固定时长恢复，也不直接将 100% 用量判为不可用。
- HTTP 错误、超时、格式错误、卡片错误、历史回退数据或超过 3 分钟的读取结果属于未知状态，保留渠道当前状态。不会把查询失败当作零个账号。多 Key 仅查询原本启用的 Key，不更改各 Key 的状态；任何 Key 查到可用账号即可用，其余结果有未知时不自动禁用。
- 自动切换不依赖系统或渠道的通用「自动禁用」开关。开启后通用错误封禁/健康检查不能覆盖状态；只恢复本监控自动禁用的渠道。人工禁用（含标签批量禁用）及其他原因禁用不会自动恢复。关闭 Magpie 开关取消自动恢复，不主动启用已禁用渠道。至少需要一个主节点运行任务，执行耗时会增加轮询间隔。
- Magpie 的额度接口返回整个实例的账号卡片，并不按调用密钥的账号授权范围筛选，也不暴露账号的手工暂停/选路状态。请使用可访问该实例全部 Codex 账号的专用网关密钥，并在 Magpie 中保持这些账号可参与选路；此功能判断实例级 Codex 账号额度可用性，不判断特定模型/分组或网关密钥本身的消费预算。
- 渠道状态、监控归属标记和选路能力在同一事务中更新，查询结果只应用于配置及状态仍与查询快照一致的渠道。本实例更新选路缓存，其他实例沿用现有缓存同步周期。监控归属标记持久化，重启后继续查询并恢复。
- 自动禁用和自动启用均发送钉钉群消息，复用钉钉设置中的 Client ID、Client Secret 和「公告群 OpenConversationId」，机器人需已加入群。仅实际切换时投递，结果在钉钉通知记录查看；失败不回滚状态，不自动重复发送。
- 每次实际自动启用/禁用均写入「系统日志」，记录渠道 ID、名称、原因和时间，管理员元数据保存目标状态及本次切换标记。重复轮询、查询失败或未改变状态不重复记录；钉钉通知失败不影响日志记录。不记录网关密钥。
- 「系统信息 → 历史任务」展示 Magpie 监控的检查、启用、禁用、未变更、检查失败及通知失败数量，可展开查看各渠道的可用性、处理结果和错误；任务中途失败也保留已完成的结果。旧任务只展示原有变更数，不补造渠道明细。结果不保存网关密钥或账号卡片。
