# 额度池功能设计

## 背景

当前系统的用户请求扣费、预扣费、结算和余额不足拒绝逻辑都基于用户自己的 `quota`。自动充值任务会在用户余额低于系统阈值时，直接给用户增加系统配置的充值额度。

本功能新增“额度池”，用于内部自用模式下管理用户额度发放的资金来源。额度池不替代用户钱包，请求消费仍扣用户自己的 `quota`。

## 目标

- 支持创建非默认额度池，并将普通用户加入额度池。
- 非默认额度池有独立预付余额，池之间额度不共享。
- 用户自动充值、管理员/池管理员点击充值按钮时，从用户所属非默认池扣减余额，再增加用户自己的 `quota`。
- 默认池保持旧逻辑：不扣池余额，不需要配置，不影响现有自动充值和手动充值行为。
- 非默认额度池可覆盖系统自动充值金额、周次数、月次数。
- 非默认额度池支持临时额度添加和按月定额扩容。
- 支持池管理员 v1/v2，池管理员权限独立于系统 Admin/Root。
- 保留池流水，用于查看池余额变化和拨付记录。

## 非目标

- 不改变用户请求扣费资金来源：请求仍只扣用户自己的 `quota`。
- 不接入订阅、在线支付、兑换码、邀请收益等外部来源。
- 不支持管理员直接增加、减少、覆盖用户额度；这些入口前端隐藏，后端直接拒绝。
- 不支持池管理员移出成员或跨池迁移成员。
- 不让默认池参与配置、临时额度、月度扩容、删除、启用/禁用等管理操作。

## 核心语义

### 请求消费

用户请求仍按现有逻辑扣用户自己的 `quota`。

- 用户自己的 `quota` 足够：按现有逻辑预扣费、结算、记录消费。
- 用户自己的 `quota` 不足：按现有逻辑拒绝请求。
- 额度池余额不参与请求扣费判断。
- 用户请求消费不写池流水，也不扣池余额。

### 默认池

默认池用于兼容旧行为。

- 用户 `quota_pool_id = 0` 表示默认池。
- 默认池可以有一条系统记录用于展示，但用户表仍用 `0` 表示默认归属。
- 默认池不可编辑、删除、禁用、临时加额度、配置月度扩容、任命池管理员。
- 默认池自动充值和手动充值沿用现有逻辑，不走新的池扣减事务。
- 默认池不需要池余额限制。

### 非默认池充值

非默认池只在“给用户发放额度”时扣减池余额。

适用路径：

- 后台自动充值任务；
- 添加成员或任命池管理员后的自动首充；
- 系统 Admin/Root 或池管理员点击充值按钮。

规则：

- 有限池必须 `pool.quota >= recharge_amount` 才能发放，不做部分发放。
- 池余额不足时：
  - 后台自动任务静默跳过；
  - 人工操作返回明确错误或 warning。
- 池禁用时：
  - 不允许新增成员、任命管理员、手动充值、自动充值、临时加额度、月度扩容；
  - 已有成员仍可消费自己现有的用户 `quota`。
- 充值成功后增加用户自己的 `quota`。
- 非默认池余额扣减和用户 `quota` 增加必须在同一数据库事务中完成。
- 用户日志和池流水按现有日志风格在主状态变更成功后写入；日志失败不回滚已成功的额度变更。

### 自动充值策略

系统阈值仍使用 `auto_recharge_setting.threshold`，额度池不覆盖阈值。

非默认池可覆盖：

- `auto_recharge_amount`
  - `-1`：继承系统自动充值金额；
  - `0`：该池不自动充值；
  - `>0`：使用池级金额。
- `weekly_limit`
  - `-1`：继承系统周限制；
  - `0`：不限制；
  - `>0`：池级周限制。
- `monthly_limit`
  - `-1`：继承系统月限制；
  - `0`：不限制；
  - `>0`：池级月限制。

次数限制按用户统计，不按池整体统计。手动充值按钮不计入周/月自动充值次数。

现有统计方式基于日志：

- 自动充值：`LogTypeSystem` 且内容以 `系统自动赠送` 开头；
- 手动充值：`LogTypeManage` 且内容匹配临时额度。

本期继续兼容现有统计方式，可在日志 `Other` 中补充结构化字段：

- `quota_pool_id`
- `quota_pool_name`
- `recharge_source`: `auto` 或 `manual`
- 操作人信息。

### 添加成员与自动首充

池成员关系用 `users.quota_pool_id` 表达，不新增成员表。

添加成员规则：

- 目标用户必须是普通用户。
- 目标用户不能是系统 Admin 或 Root。
- 目标用户必须启用且未删除。
- 池管理员只能添加当前在默认池的用户。
- 系统 Admin/Root 可以从默认池添加，也可以直接迁移非默认池成员到其他池。
- 加入非默认池时，先按迁移规则处理用户当前余额，再尝试自动首充。

自动首充规则：

- 进入非默认池时触发，包括添加成员、从其他池迁移进入、任命池管理员时加入该池。
- 首充算自动充值，写自动充值日志，计入用户周/月自动次数。
- 首充走完整自动充值判断：阈值、金额、周/月次数、池启用、池余额。
- 首充失败不回滚成员或管理员变更，不写失败日志。
- 人工接口返回 `success: true` 并附带 warning，例如“成员已添加，自动充值未完成：额度池余额不足”。
- 迁移到默认池不触发首充。

### 迁移与移出成员

迁移规则：

- 读取用户当前 `quota`。
- 如果 `quota > 0` 且旧池是非默认有限池，将该余额退回旧池。
- 如果旧池是默认池，不退回池余额。
- 如果 `quota < 0`，迁移时清零为 `0`，不调整任何池余额。
- 用户 `quota` 最终置为 `0`。
- 更新 `quota_pool_id` 到目标池或 `0`。
- 用户离开原池时，删除其原池管理员身份。

权限：

- 池管理员不能移出成员，不能跨池迁移成员。
- 系统 Admin/Root 可以把成员迁移到任意合法目标池。
- 目标池必须存在、未删除、启用；否则迁移失败且不清零用户余额。

### 池管理员

池管理员权限独立于系统角色。

数据关系：

- 新增 `quota_pool_admins`。
- 一个池可以有多个管理员。
- 一个用户最多只能管理一个池。
- 池管理员默认也是该池成员。
- 默认池不能任命池管理员。

等级：

- v1：管理本池成员、给本池成员充值、查看本池信息和流水。
- v2：拥有 v1 权限，并可任命/移除本池 v1 管理员。

任命规则：

- 系统 Admin/Root 可以任命非默认池的 v1/v2 管理员。
- 池 v2 只能任命/移除本池 v1 管理员，不能管理 v2。
- 池 v1 不能任命管理员。
- 被任命对象必须是普通用户。
- 如果目标用户在默认池：任命时加入该池、清零原余额、触发自动首充，再授予管理员权限。
- 如果目标用户已在同一池：直接授予管理员权限，不清零、不首充。
- 如果目标用户在其他非默认池：任命失败，需系统 Admin/Root 先迁移。
- 移除池管理员权限只移除管理权限，保留成员身份。

池管理员前端入口：

- 新增“额度池”菜单。
- Root、系统 Admin、池 v1/v2 管理员可见。
- 池管理员只看到自己管理的非默认池。
- 普通成员用户不显示池余额和流水。

## 池额度管理

### 临时额度

系统 Admin/Root 可给非默认池添加临时额度。

限制：

- 默认池不支持临时额度。
- 禁用池不支持临时额度。
- 每次临时额度不能超过 `base_quota * 50%`。
- 每个池每个自然月最多添加 2 次临时额度。
- 自然月按服务器本地时区统计。
- 临时额度只增加池 `quota`，不直接增加任何用户 `quota`。
- 写池流水，不写用户日志。

### 月度扩容

Root 可配置非默认池月度扩容。

字段：

- `monthly_refill_enabled`
- `monthly_refill_amount`
- `monthly_refill_day`：限制为 `1..28`
- `last_refill_month`：如 `202606`，用于防止同月重复执行。

规则：

- 默认池不参与月度扩容。
- 禁用池跳过月度扩容。
- 开启月度扩容时，金额必须大于 0。
- 使用服务器本地时区。
- 如果服务停机错过执行日，恢复后当月补执行一次。
- 扩容只增加池 `quota`，不直接增加用户 `quota`。
- 写池流水，不写用户日志。
- 月度扩容任务合并到现有自动充值后台循环里，并沿用主节点保护。

## 数据模型

### `quota_pools`

建议字段：

- `id`
- `name`：未删除记录内唯一。
- `enabled`
- `is_default`
- `base_quota`：内部 quota，创建时预付基准；非默认池必须大于 0。
- `quota`：内部 quota，当前可拨付余额；默认池可为 `-1`。
- `auto_recharge_amount`：内部 quota；`-1` 继承，`0` 关闭，`>0` 覆盖。
- `weekly_limit`
- `monthly_limit`
- `monthly_refill_enabled`
- `monthly_refill_amount`：内部 quota。
- `monthly_refill_day`
- `last_refill_month`
- `created_at`
- `updated_at`
- `deleted_at`

约束：

- 保留 `is_default` 表达默认池身份。
- 默认池 `is_default = true`，不可操作。
- 非默认池 `quota >= 0`，不允许 `-1`。
- 非默认池创建金额必须大于 0。
- 名称唯一通过应用层校验未删除记录，避免跨数据库软删除唯一索引差异。

### `users`

新增：

- `quota_pool_id`：普通索引，不加数据库外键。

语义：

- `0` 表示默认池。
- 用户同一时间只能属于一个额度池。

### `quota_pool_admins`

新增：

- `id`
- `pool_id`
- `user_id`
- `level`：`1` 或 `2`
- `created_at`

约束：

- `user_id` 唯一，保证一个用户最多管理一个池。
- 管理员必须是普通用户。
- 管理员也必须是对应池成员。

### `quota_pool_transactions`

新增池流水表：

- `id`
- `pool_id`
- `type`
- `amount`：有符号内部 quota；入账为正，出账为负。
- `quota_before`
- `quota_after`
- `user_id`：可为 `0`。
- `operator_id`：可为 `0`。
- `created_at`

流水类型：

- `initial_fund`：创建池初始入账。
- `manual_refill`：池临时额度入账。
- `monthly_refill`：池月度扩容入账。
- `allocate_auto`：自动充值拨付给用户，包括后台自动充值和进入非默认池后的首充。
- `allocate_manual`：手动充值按钮拨付给用户。
- `reclaim_user`：迁移或移出成员时退回用户当前余额。

说明：

- 请求消费不写池流水。
- 池余额不足导致跳过不写流水。
- 默认池按最小改动沿用旧逻辑，不要求写池流水。

## API 建议

路径沿用项目单数风格，使用 `/api/quota_pool`。

系统 Admin/Root：

- `GET /api/quota_pool`：额度池列表。
- `GET /api/quota_pool/:id`：额度池详情。
- `GET /api/quota_pool/:id/transactions`：池流水分页。
- `POST /api/quota_pool/:id/refill`：添加池临时额度。
- `POST /api/quota_pool/:id/members`：添加成员。
- `PUT /api/user/:id/quota_pool`：迁移成员。
- `POST /api/quota_pool/:id/members/:user_id/recharge`：给成员充值。
- `POST /api/quota_pool/:id/admins`：任命池管理员。
- `DELETE /api/quota_pool/:id/admins/:user_id`：移除池管理员权限。

Root only：

- `POST /api/quota_pool`：创建额度池。
- `PUT /api/quota_pool/:id`：编辑池名称、自动充值覆盖、月度扩容配置。
- `POST /api/quota_pool/:id/enable`：启用池。
- `POST /api/quota_pool/:id/disable`：禁用池。
- `DELETE /api/quota_pool/:id`：删除池。

池管理员：

- `GET /api/quota_pool/self`：自己的池信息。
- `GET /api/quota_pool/self/transactions`：自己的池流水。
- `GET /api/quota_pool/self/members`：成员列表。
- `GET /api/quota_pool/self/candidates`：可添加的默认池普通用户。
- `POST /api/quota_pool/self/members`：添加默认池用户为成员。
- `POST /api/quota_pool/self/members/:user_id/recharge`：给本池成员充值。
- v2 额外：
  - `POST /api/quota_pool/self/admins`：任命本池 v1。
  - `DELETE /api/quota_pool/self/admins/:user_id`：移除本池 v1 权限。

用户自信息：

- `/api/user/self` 返回池管理员摘要：

```json
{
  "quota_pool_admin": {
    "pool_id": 123,
    "level": 2
  }
}
```

无池权限时为 `null`。

## 权限矩阵

- Root：
  - 创建、删除、启用、禁用、编辑所有池；
  - 配置月度扩容；
  - 添加临时额度；
  - 任命/移除 v1/v2；
  - 添加、迁移、移出成员；
  - 给成员充值；
  - 查看所有池和流水。
- 系统 Admin：
  - 查看所有池和流水；
  - 添加临时额度；
  - 任命/移除 v1/v2；
  - 添加、迁移、移出成员；
  - 给成员充值；
  - 不能创建、删除、启用、禁用、编辑长期配置。
- 池 v2：
  - 查看自己的池和流水；
  - 添加默认池普通用户为成员；
  - 给本池成员充值；
  - 任命/移除本池 v1；
  - 不能移出成员、跨池迁移、管理 v2、添加临时额度、改池配置。
- 池 v1：
  - 查看自己的池和流水；
  - 添加默认池普通用户为成员；
  - 给本池成员充值；
  - 不能任命管理员、移出成员、跨池迁移、添加临时额度、改池配置。

## 前端建议

- 新增“额度池”菜单。
- 系统 Admin/Root 显示池列表、详情、流水、成员、管理员、临时额度入口。
- Root 显示创建、删除、启用/禁用、长期配置入口。
- 池管理员只显示自己的池详情、成员、流水和允许的操作按钮。
- 用户管理里隐藏直接增加、减少、覆盖用户额度入口；后端同步拒绝对应接口。
- 保留“充值按钮”，但根据操作者权限调用系统管理或池管理接口。

## 验收标准

- 默认池用户自动充值和手动充值保持旧逻辑。
- 非默认池用户自动充值成功时，池余额减少、用户 `quota` 增加。
- 非默认池余额不足时，后台自动充值静默跳过，人工充值返回错误或 warning。
- 手动充值不计入周/月自动充值次数。
- 添加成员或任命池管理员进入非默认池时，先清零历史余额，再尝试自动首充。
- 首充失败不回滚成员/管理员变更。
- 管理员直接增加、减少、覆盖用户额度接口被后端拒绝，前端隐藏。
- 池临时额度受单次 50% 和每池每月 2 次限制。
- 月度扩容按池配置每月最多执行一次，错过执行日可补执行。
- 池 v1/v2 权限独立于系统 Admin/Root，且只能作用于池相关能力。
- SQLite、MySQL、PostgreSQL 迁移与事务逻辑兼容。
