# 额度池月度自动充值与额度补齐设计

## 背景

当前额度池的月度扩容规则只支持固定增加金额。配置月度充值金额为 6000 时，池内可用额度为 3000，下一次执行会增加 6000，余额变为 9000。

需要增加“额度补齐”模式：同样配置 6000 时，执行日只增加不足部分，将额度池可用额度恢复到 6000。

## 目标与边界

- 保留现有固定月度充值行为，并将其作为默认模式。
- 增加额度池级别的“额度补齐”开关。
- 补齐是每月执行一次的资金规则，不是实时余额保底。
- 不改变用户自动充值逻辑；用户自动充值仍然使用 `auto_recharge_amount`。
- 不改变默认额度池、产研中心默认额度池和新用户额度池的既有保护规则。

## 领域规则

### 配置语义

额度池新增 `monthly_refill_top_up` 布尔字段，默认值为 `false`。

- `monthly_refill_enabled = false`：不执行月度资金规则。
- `monthly_refill_enabled = true` 且 `monthly_refill_top_up = false`：月度充值金额是固定增加量。
- `monthly_refill_enabled = true` 且 `monthly_refill_top_up = true`：月度充值金额是目标可用额度。

现有数据默认关闭补齐，因此升级后行为保持不变。

### 执行金额

固定充值模式：

```text
actual_amount = monthly_refill_amount
```

额度补齐模式：

```text
actual_amount = max(monthly_refill_amount - quota, 0)
```

例如月度充值金额为 6000：

| 执行前可用额度 | 固定充值后 | 补齐后 | 补齐实际增加 |
| --- | ---: | ---: | ---: |
| 3000 | 9000 | 6000 | 3000 |
| 6000 | 12000 | 6000 | 0 |
| 7000 | 13000 | 7000 | 0 |

实际增加金额同时增加额度池 `quota` 和 `base_quota`，保持当前可用额度与累计总额度的账务关系。

### 月度执行边界

- 执行条件继续沿用现有规则：额度池启用、月度自动充值启用、充值金额大于 0、当前日期达到执行日且本月未执行。
- 补齐模式下，当前可用额度达到目标时，实际增加金额为 0。
- 无论实际增加金额是否为 0，都更新 `last_refill_month`，保证本月只执行一次。
- 当实际增加金额为 0 时，不写零金额资金流水。
- 数据库事务失败时回滚额度变化和 `last_refill_month`，下次任务继续尝试。

## 数据流与实现边界

### 数据模型

在 `QuotaPool` 增加：

```text
MonthlyRefillTopUp bool `json:"monthly_refill_top_up" gorm:"default:false;column:monthly_refill_top_up"`
```

通过现有 GORM 自动迁移机制增加字段，保持 SQLite、MySQL 和 PostgreSQL 兼容。新字段默认 `false`。

### 月度任务

月度任务在单个数据库事务中重新读取额度池，并根据当前 `quota` 计算实际增加金额。使用当前项目已有的事务和行并发控制模式，确保月度任务与用户充值、管理员调额并发时不会重复补齐。

事务成功后：

- 更新 `quota`、`base_quota` 和 `last_refill_month`。
- 实际金额大于 0 时写入 `monthly_refill` 流水。
- 实际金额为 0 时只更新执行月份，不写资金流水。

### 配置接口

- `quotaPoolUpdateRequest` 增加 `monthly_refill_top_up` 可选字段。
- 保持现有 Root 权限校验。
- 启用月度自动充值时，仍要求月度充值金额大于 0。
- 配置变更写入额度池操作日志。

### 前端配置

- 将“月度扩容”显示为“月度自动充值”。
- 增加“额度补齐”复选框，仅在月度自动充值启用时展示。
- 说明文案明确：关闭时金额为每月固定增加量，开启时金额为目标可用额度。
- 补齐中文、繁体中文、英文、法文、俄文、日文和越南文资源。

## 测试方案

### 服务测试

- 固定充值：可用额度 3000、月度金额 6000，结果为 9000，流水为 6000。
- 补齐不足：可用额度 3000、目标 6000，结果为 6000，流水为 3000。
- 补齐达到目标：可用额度 6000，额度不变，不写零金额流水。
- 补齐超过目标：可用额度 7000，额度不变，不写零金额流水。
- 当月重复执行：第二次执行不再增加额度。
- 实际金额为 0 时仍更新 `last_refill_month`，当月后续余额下降不再次补齐。
- 事务失败时额度和执行月份均保持不变。

### 控制器与前端验证

- 配置接口能保存和返回补齐开关。
- 非 Root 用户仍不能修改月度资金规则。
- 操作日志能记录补齐开关变化。
- 前端 ESLint、格式化、i18n 完整性检查和生产构建通过。
- `git diff --check` 通过。

## 不在本次范围内

- 不增加实时保底或按余额变化持续补齐。
- 不改变用户自动充值的阈值、金额和次数限制。
- 不新增在线支付或外部资金渠道。
