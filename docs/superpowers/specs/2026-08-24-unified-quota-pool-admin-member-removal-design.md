# 统一池管理员与成员移出设计

## 背景与目标

`v0.13.2-icode` 最终版本已在提交 `736821948` 中移除池管理员 v2，只保留单一“池管理员”。rc.25 迁移提交 `53e35d126` 根据较早设计重新引入 v1/v2，造成权限模型回归。

本次变更需要恢复旧版最终语义，并增加明确的成员移出能力：池管理员可以把本池普通成员移回新用户默认额度池；系统 Admin、Root 和池超级管理员可以移出任何成员。移出时回收原池发放的余额，不重新赠送体验额度。

## 池管理员模型

### 兼容策略

- 保留 `quota_pool_admins.level` 数据库列，避免为 SQLite、MySQL 和 PostgreSQL 增加删列迁移风险。
- 幂等迁移将所有 `level != 1` 的历史记录规范化为 `1`。
- 删除 `QuotaPoolAdminLevelV2` 以及所有等级比较；新增管理员固定写入 `1`。
- `GrantQuotaPoolAdmin` 不再接收 level 参数。
- 管理员摘要只暴露 `pool_id`，不再向客户端返回等级。
- 成员响应使用 `quota_pool_admin: boolean`，替代 `quota_pool_admin_level`。

### Capability

额度池 capability 统一为：

- `can_view`
- `can_edit`
- `can_edit_monthly_refill`
- `can_refill`
- `can_manage_members`
- `can_remove_members`
- `can_manage_admins`
- `can_delete`

删除 `can_manage_v1_admins` 和 `can_manage_v2_admins`。

权限规则：

- 普通池管理员：查看和配置自己的池、管理本池普通成员、充值、回收及移出普通成员；不能管理或移出池管理员。
- 池超级管理员：查看全部池、管理成员、移出任何成员、任命或撤销池管理员，并保留现有全局池配置能力。
- 系统 Admin：查看全部池、管理资金和成员、移出任何成员、任命或撤销池管理员。
- Root：保留全部能力。
- 普通成员：只查看自己的池，不具备管理能力。

## 成员移出领域服务

新增按来源池约束的成员移出服务。服务端自行查找唯一的 `pool_type=new_user` 额度池，客户端不决定目标池。

单个数据库事务内执行：

1. 查询并锁定用户、来源池和新用户默认池；池锁按 ID 排序。
2. 验证来源池为普通池，默认池存在且启用；允许全局管理者清理已停用普通池中的成员。
3. 验证用户仍属于来源池，防止检查后归属被并发修改。
4. 普通池管理员操作时，验证目标用户不是池管理员。
5. 用户正余额全部退回来源池，写 `reclaim_user` 资金流水。
6. 用户余额为零或负数时直接清零，不增加来源池余额，不写零金额流水。
7. 用户 `quota` 设为 `0`，`quota_pool_id` 更新为新用户默认池 ID。
8. 全局管理者移出池管理员时，同一事务删除其池管理员关系。
9. 事务提交后失效用户缓存。

移出后不触发自动首充，也不重新执行新用户注册赠送逻辑。任何验证或写入失败时，余额、池归属、管理员关系和资金流水共同回滚。

## 权限与 API

新增规范接口：

- `DELETE /api/quota_pool/:id/members/:user_id`：系统 Admin、Root、池超级管理员。
- `DELETE /api/quota_pool/self/members/:user_id`：当前池管理员。

保留并恢复旧版兼容入口：

- `PUT /api/quota_pool/self/members/:user_id`

兼容入口只接受目标为当前新用户默认池的请求，之后调用同一领域服务。现有 `PUT /api/quota_pool/users/:user_id` 继续用于全局管理者执行任意合法池迁移。

后端必须独立验证：

- 操作者对来源池的权限；
- 用户是否仍属于来源池；
- 普通池管理员不能移出池管理员；
- 来源池类型与目标默认池状态；
- 目标用户角色是否允许成为额度池成员。

成功响应返回原池 ID、目标池 ID、回收金额和管理员关系是否解除。操作审计写入来源池，事件为 `quota_pool.member_remove`，包含用户 ID、目标池 ID 及回收金额；不得暴露数据库内部错误。

## 前端交互

成员列表新增“移出”操作：

- 由 `can_remove_members` 控制基础可见性。
- 普通池管理员仅在 `quota_pool_admin=false` 的成员行显示。
- `can_manage_admins=true` 的全局管理者可以在池管理员行显示。
- 新用户默认池、存量默认池和其他受保护系统池不显示移出入口。

点击“移出”后打开二次确认框，展示成员名称和当前余额，并明确说明：

- 当前余额将全部退回原额度池；
- 用户将回到新用户默认池；
- 不会重新赠送体验额度。

取消时不调用 API。成功后刷新当前池详情、成员当前分页、池余额及管理员信息；失败时保留弹窗、筛选条件和当前分页，并显示后端稳定错误文案。

管理员操作同步调整：

- `setQuotaPoolAdmin` 不再传 level。
- 任命和撤销按钮仅依据 `can_manage_admins`。
- 所有 v1/v2 文案、类型和前端判断均删除。
- 新增文案通过 `i18n-translate` 脚本化补齐 `en`、`zh`、`zh-TW`、`fr`、`ru`、`ja`、`vi`。

## 测试与验收

### 模型与迁移

- SQLite 迁移执行两次仍幂等，历史 level 2 规范化为 1。
- 正余额移出时来源池增加相同额度，用户清零，资金流水金额正确。
- 零余额和负余额移出时不增加来源池、不写零金额流水。
- 默认池缺失或禁用、来源池错误、用户归属并发变化时整体回滚。
- 全局管理者移出池管理员时管理员关系与资金变更共同提交。

### 权限与 API

- 普通池管理员可移出本池普通成员。
- 普通池管理员不能移出自己、其他池管理员或其他池成员。
- 系统 Admin、Root、池超级管理员可移出池管理员。
- 普通用户不能调用移出接口。
- 新 DELETE 路由和旧 PUT 兼容路由均注册并返回一致领域结果。
- 审计日志关联来源池，资金流水使用 `reclaim_user`。
- capability 不再包含 v1/v2 字段。

### 前端

- 按 capability 和成员管理员状态正确显示或隐藏“移出”。
- 二次确认显示成员、余额、回收和体验额度说明。
- 取消不请求，确认只请求一次。
- 成功刷新相关查询，失败保留分页、筛选和弹窗。
- 七语言同步报告无缺失、额外或未翻译条目。

### 最终验证

- 后端：额度池相关测试、`go test -race ./model ./service ./controller ./middleware`、`go vet ./...`、`go build ./...`。
- 前端：受影响测试、全量测试、格式、涉及文件 lint、typecheck、i18n 同步和生产构建。
- 仓库：`git diff --check`，确认生产代码中不再存在 v1/v2 capability、常量和文案；仅数据库兼容列 `level` 保留。

## 非目标

- 不删除 `quota_pool_admins.level` 数据库列。
- 不改变池超级管理员角色或系统 Admin/Root 的既有全局可见范围。
- 不允许普通池管理员执行任意跨池迁移。
- 不在成员移出后重新发放体验额度或自动充值。
