# 额度池统计增强设计

## 目标

在现有额度池“统计”页补齐按自然周、自然月及自定义日期范围分析成员活跃和用量的能力，并支持将当前统计结果导出为 Markdown 或 Excel。统计只读取 `quota_data` 小时聚合表，不扫描原始日志。

## 范围与口径

- 系统管理员可查看任意额度池；池管理员只能查看自己管理的额度池；普通成员不能查看或导出统计。
- 统计对象是查询时仍属于该额度池的当前成员。成员转池后，历史区间用量按当前归属计算。
- 成员在某个本地自然日内至少存在一条 `count > 0` 的聚合记录，即为该日活跃。
- 历史自然周为周一 00:00:00 至周日 23:59:59；历史自然月为完整月份；当前周/月截止查询时刻。
- 自定义范围按自然日选择，包含起止日期，最多 366 天。
- `quota_data` 以 UTC 整点聚合，统计服务时区必须是整小时 UTC 偏移；项目默认 `Asia/Shanghai` 满足该约束。非整小时偏移无法准确切分自然日，明确返回配置错误而不静默漏算或跨日计数。
- 查询和导出共享同一统计服务及 5 分钟 Redis 缓存。

## 页面设计

统计页顶部提供“本周”“本月”快捷按钮，以及按周、按月和自定义三种日期选择方式。页面显示统计区间、数据生成时间和缓存约 5 分钟的说明。

内容依次为：

1. 汇总卡片：成员数、活跃成员数、活跃率、调用次数、总用量、人均活跃用量。
2. 活跃趋势：逐日活跃成员数和活跃率。
3. 用量趋势：逐日调用次数和额度用量。
4. 成员明细：成员、活跃状态、活跃天数、最后活跃时间、调用次数、用量、用量占比、日均用量和主要模型占比。未活跃成员保留为零值行。
5. 资金变动：保留现有充值、分配和回收汇总。

成员明细支持按活跃状态筛选，并支持按用量、调用次数和活跃天数排序。趋势图需要提供屏幕阅读器可访问的等价数据表。

## 接口设计

现有接口继续使用：

- `GET /api/quota_pool/:id/stats`
- `GET /api/quota_pool/self/stats`

查询参数：

- `range_type=week&anchor=YYYY-MM-DD`
- `range_type=month&anchor=YYYY-MM`
- `range_type=custom&start_date=YYYY-MM-DD&end_date=YYYY-MM-DD`
- 兼容旧参数 `period=week|month`；无参数仍默认为本周。

新增导出接口：

- `GET /api/quota_pool/:id/stats/export`
- `GET /api/quota_pool/self/stats/export`

导出接口复用同一组日期参数，额外接受 `format=markdown|xlsx`。统计响应包含标准化后的范围、`generated_at`、汇总、每日走势、成员明细和资金变动。

## 数据实现

后端先读取额度池当前成员 ID 和名称，再对 `quota_data` 做两类聚合：

- 按成员聚合调用次数、额度用量和模型分类用量；
- 按成员和小时桶聚合调用次数及用量，在 Go 中按服务本地时区折叠为自然日，从而计算每日走势、成员活跃天数和最后活跃时间。

这样避免数据库方言相关的日期函数，同时显著减少模型、Token、渠道等维度产生的返回行。每日结果会补齐无数据日期。

## 导出设计

- Markdown 包含概览、每日走势、成员明细和资金变动四节。
- Excel 使用真实 `.xlsx`，包含“概览”“每日走势”“成员明细”“资金变动”四个工作表。
- 页面按当前显示币种格式化用量；服务端导出无法读取浏览器显示币种，因此 Markdown/XLSX 的数值列明确标记为“内部额度单位”，避免将原始额度误认为美元或人民币。
- 文件名格式为 `<额度池名称>_<开始日期>_<结束日期>.<扩展名>`，并清理不安全文件名字符。
- Markdown 对竖线和换行转义；Excel 对以 `= + - @` 开头的文本加前缀，阻止公式注入。

## 错误与边界

- 日期格式错误、起止颠倒、未来历史锚点或超过 366 天返回 HTTP 400。
- 无权限返回 HTTP 403；不存在的额度池返回现有错误。
- 无成员或无调用记录仍返回完整零值汇总和日期轴，并允许导出。
- 导出生成失败返回错误，不修改或失效页面统计缓存。
