# 额度池统计范围与导出设计

## 目标

优化额度池统计的时间选择和导出流程：页面提供常用快捷范围及自定义范围，走势图按范围自动选择小时或天颗粒度；导出使用独立弹窗选择时间范围、小时/天/周颗粒度和 Markdown/XLSX 类型。

统计对象仍是查询时属于额度池的当前成员，数据只读取 `quota_data` 小时聚合表，不扫描原始日志。

## 时区

- 公告钉钉消息、额度池统计范围、自然日和自然周分桶固定使用北京时间 `Asia/Shanghai`（UTC+8）。
- 不提供时区配置，不依赖容器 `time.Local` 或 `TZ`。
- `quota_data` 是 UTC 整点桶，固定北京时间后小时边界与聚合桶始终一致。

## 页面时间范围

页面固定提供以下快捷项：

| 快捷项 | 统计范围 | 页面走势颗粒度 |
| --- | --- | --- |
| 1天 | 当前小时桶及之前 23 个小时桶，结束于当前时刻 | 小时 |
| 7天 | 当前小时桶及之前 167 个小时桶 | 天 |
| 14天 | 当前小时桶及之前 335 个小时桶 | 天 |
| 29天 | 当前小时桶及之前 695 个小时桶 | 天 |
| 当天 | 北京时间当天 00:00 至当前 | 小时 |
| 本周 | 北京时间周一 00:00 至当前 | 天 |
| 本月 | 北京时间当月 1 日 00:00 至当前 | 天 |
| 自定义 | 用户选择起止日期时间，最长 366×24 小时 | 不超过 2 天按小时，否则按天 |

滚动范围按 `quota_data` 的小时桶近似，首个桶从整点开始，当前桶只包含已落库数据。页面显示后端返回的实际统计起止时间、走势图颗粒度、生成时间、北京时间和 5 分钟缓存说明。

页面修正中文翻译，将通用时间范围中的“本月获得”改为“本月”。

## 页面布局

采用已确认的方案 A：

1. 顶部第一行放置八个快捷范围；选择“自定义”后显示起止日期时间。
2. 右侧保留“刷新统计”和“导出”。
3. 汇总卡、活跃走势、调用/用量走势、成员明细及资金汇总保持现有信息层级。
4. 页面筛选只影响当前展示；导出弹窗维护独立范围，不改变页面选择。

## 导出弹窗

点击“导出”后打开弹窗：

- 默认继承页面当前响应中的实际起止时间和自动颗粒度。
- 可重新选择同一组快捷范围或自定义开始、结束日期时间。
- 自定义范围最长 366×24 小时。
- 颗粒度可选 `小时`、`天`、`周`，默认按页面自动规则选择，允许覆盖。
- 类型可选 `Markdown`、`Excel (.xlsx)`。
- 点击“导出文件”后才请求后端并下载；取消不发请求。

颗粒度只改变走势明细：

- 小时：按北京时间小时展示活跃成员数、调用次数、Token 量和费用。
- 天：按北京时间自然日展示；首尾保留部分日。
- 周：周一至周日；首尾保留部分周。

概览和成员明细始终按完整导出区间汇总，成员“活跃天数”始终按自然日计算。

XLSX 包含“概览、走势明细、成员明细”三个工作表；Markdown 包含同名三节，资金变动暂不导出。文件名包含额度池名称和实际起止时间。导出继续防护 Markdown 链接/图片注入、HTML 注入和 XLSX 公式注入。用量直接汇总 `quota_data.token_used`，费用由计费额度除以 `QuotaPerUnit` 换算为美元；Token 量、日均 Token 量、费用和日均费用均保留两位小数。

## 接口契约

不保留旧 `period`、`range_type`、`anchor` 契约。页面和导出统一使用：

- `preset=rolling_1d|rolling_7d|rolling_14d|rolling_29d|today|this_week|this_month|custom`
- `preset=custom` 时必须传 `start_timestamp`、`end_timestamp`
- `granularity=hour|day|week`

统计接口：

- `GET /api/quota_pool/:id/stats`
- `GET /api/quota_pool/self/stats`

导出接口：

- `GET /api/quota_pool/:id/stats/export`
- `GET /api/quota_pool/self/stats/export`
- 额外参数 `format=markdown|xlsx`

响应将原 `daily` 统一替换为 `trend`，每项包含 `bucket_start`、`bucket_end`、展示标签、活跃成员数、活跃率、调用次数、Token 量和计费额度。响应同时返回标准化后的 `preset`、`granularity`、实际时间戳及格式化时间。

## 聚合与缓存

- 后端范围解析器使用固定北京时间生成实际起止时间和自动颗粒度。
- 模型层继续按成员×小时流式读取 `quota_data`，在 Go 中单次汇总计费额度、真实 Token 量、成员、活跃自然日和走势桶。
- 周颗粒度按北京时间周一分桶。
- 页面与导出调用同一统计服务；缓存键包含额度池 ID、实际开始小时、实际结束小时和颗粒度。
- Redis TTL 维持 5 分钟；页面和导出若范围及颗粒度相同可复用缓存。

## 权限与错误

- 系统管理员可查看和导出任意额度池。
- 池管理员只能查看和导出自己管理的额度池。
- 普通成员不展示统计入口，接口返回 403。
- 不支持的 preset、granularity、format、缺失自定义参数、起止倒置或超过 366 天返回 400。
- 无成员或无使用记录仍返回完整零值时间轴并允许导出。
