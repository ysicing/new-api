# 个人工具与自动充值资格自查设计

## 目标

在应用左侧导航的“个人”分组中，于“个人资料”下方新增同级入口“工具”。工具使用独立页面承载，首个工具为“自动充值资格”，登录用户点击后只读查询本人当前自动充值资格、命中规则和处理建议。

本功能只查询当前状态，不触发自动充值，不允许传入或查询其他用户标识。

## 导航与页面

左侧导航顺序固定为：

1. 钱包
2. 个人资料
3. 工具

“工具”使用独立路由 `/tools`，归属现有“个人”分组。页面标题为“工具”，说明为“账户自助查询与诊断”。首个工具卡片为“自动充值资格”，说明为“查询本人资格、命中规则和处理建议”。点击卡片打开资格查询弹窗。

导航继续遵循现有管理员和用户两层侧边栏显示配置：

- 新增配置键 `personal.tools`，默认开启。
- 管理员可统一隐藏“工具”入口；允许自定义侧边栏的用户可进一步隐藏。
- 历史配置没有 `tools` 字段时按默认开启处理。
- 隐藏导航只影响入口显示，不能代替接口鉴权。

## 查询交互

点击“自动充值资格”后打开标准 Dialog，并立即请求本人资格接口。每次重新打开均重新查询，不复用旧结果；查询期间展示加载状态。

弹窗展示：

- 资格状态
- 当前余额
- 自动充值阈值
- 单次自动充值额度
- 本周已充值次数与上限
- 本月已充值次数与上限
- 当前额度池名称
- 未满足条件时的命中规则
- 真正受限时的处理建议

弹窗仅展示本人可见信息，不展示额度池剩余额度、其他成员、管理员配置值或其他用户身份信息。查询失败时展示“资格查询失败，请稍后重试”和重试按钮，不直接展示后端内部错误。

## 状态语义

前端展示三种状态：

| 状态 | 判定 | 展示 |
| --- | --- | --- |
| 可以自动充值 | `eligible=true` | 绿色状态，展示当前可自动充值 |
| 暂不需要充值 | 原因仅为 `quota_above_threshold` | 中性状态，提示当前余额高于充值阈值，不引导联系管理员 |
| 当前受限 | 其他不可充值原因 | 红色状态，展示命中规则和按额度池类型生成的处理建议 |

不可充值原因继续复用现有自动充值评估规则，包括全局关闭、用户禁用、额度池不存在或停用、充值金额未配置、周/月次数受限、次数读取失败和额度池余额不足。前端将稳定原因码映射为国际化文案；未知原因统一显示“当前无法自动充值，请按处理建议联系相关人员”，不泄露内部错误文本。

## 处理建议

只有“当前受限”状态展示处理建议。后端根据用户当前所属额度池返回稳定枚举，前端映射为以下固定文案：

| 用户所属额度池 | 建议枚举 | 中文提示 |
| --- | --- | --- |
| 普通额度池 | `quota_pool_admin` | 请联系额度池管理员处理。 |
| 新用户额度池 | `department_quota_pool_admin` | 请联系所属部门额度池管理员处理。 |
| 存量额度池（`quota_pool_id=0`） | `operations_oa` | 请发起运维 OA 工单审批。 |

本期不展示具体管理员名单，不提供 OA 跳转链接，也不新增相关配置。

## 后端接口

新增本人只读接口：

```http
GET /api/user/auto_recharge/eligibility
```

接口要求登录态，通过 `middleware.UserAuth()` 获取当前用户 ID，不接受 query 或 body 中的用户标识，并禁用 HTTP 缓存。接口复用现有自动充值资格评估逻辑，但返回面向普通用户的收敛响应：

```json
{
  "success": true,
  "data": {
    "status": "eligible | not_needed | blocked",
    "eligible": false,
    "reason": "weekly_limited",
    "user_quota": 1600000,
    "threshold": 5000000,
    "amount": 25000000,
    "pool_name": "产研一部",
    "pool_type": "normal",
    "weekly": { "used": 3, "limit": 3 },
    "monthly": { "used": 8, "limit": 10 },
    "guidance": "quota_pool_admin"
  }
}
```

`guidance` 仅在 `status=blocked` 时返回非空值。接口保持纯只读，不更新用户额度、不写充值记录，也不触发自动充值通知。

## 代码边界

- `service/auto_recharge.go` 保留唯一资格评估规则，增加按用户 ID 查询本人的安全入口和用户侧响应组装，不复制充值判定。
- `controller/` 增加轻量本人查询处理器，只负责当前用户、HTTP 状态和通用错误响应。
- `router/api-router.go` 将接口挂在现有 `/api/user` 登录用户路由组。
- `web/src/features/tools/` 负责工具页、资格 API、类型、工具卡片和结果弹窗。
- `web/src/routes/_authenticated/tools/` 负责 `/tools` 认证路由。
- 左侧导航和两层侧边栏配置增加 `personal.tools`，不改变其他导航项。
- 所有新增用户可见文本写入七种前端语言文件，并由 i18n 同步工具维护静态键。

## 错误与安全

- 未登录请求由 `UserAuth` 拒绝。
- 当前用户不存在时返回通用 404；资格评估依赖读取失败时返回通用 500。
- 响应不包含邮箱、其他用户信息、额度池余额或内部错误字符串。
- GET 接口不产生管理审计或充值日志，不进行任何余额变更。
- 前端不根据用户可控文本拼装 HTML。

## 验证

后端测试覆盖：

- 接口只能查询登录用户本人。
- 调用接口前后用户余额、额度池余额和充值记录不变。
- 普通额度池、新用户额度池和存量额度池分别返回正确处理建议。
- 余额高于阈值返回 `not_needed` 且不返回处理建议。
- 周/月限制等现有规则仍与管理员资格查询一致。
- 路由使用登录用户鉴权，不使用管理员鉴权。

前端测试覆盖：

- “工具”位于左侧导航“个人资料”之后。
- 历史侧边栏配置默认展示工具，管理员或用户关闭 `personal.tools` 时隐藏。
- 工具页只显示当前工具入口，点击后才请求接口。
- 弹窗正确展示加载、可以充值、暂不需要、受限及失败重试状态。
- 三类额度池受限提示准确，未知原因不泄露内部错误。
- 键盘操作、焦点管理、窄屏布局和明暗主题可用。
- 七种语言键同步、TypeScript、定向 lint、Vitest 和生产构建通过。
